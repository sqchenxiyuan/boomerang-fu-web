# 音频、回放与 AI 对战

本轮需求：开源 JavaScript 音频库实现 BGM/音效；可录制、导出、导入、播放和跳转的对局回放；内置机器人互战及外部 AI 接口；保持固定步长的加速模拟。用户已确认同时支持内置机器人与外部 AI。

## 调研与选择

2026-10-29 已读取下列官方仓库/技术文章，原始网页保留在忽略目录 `analysis/derived/v6-research/`。

| 方案 | 用途和取舍 | 本轮选择 |
| --- | --- | --- |
| [Tone.js](https://github.com/Tonejs/Tone.js)，15.1.22，MIT | Web Audio 合成器、鼓、包络、音频时钟和乐曲调度，能生成完整配器；体积较大 | 用于程序化 BGM 与分层效果音，每个游戏拥有独立音频上下文 |
| [Howler.js](https://github.com/goldfire/howler.js)，2.2.4，MIT | 适合预录音频文件的加载、音频精灵与播放；自身不提供音乐合成 | 当前没有授权样本库，不采用 |
| [ZzFX](https://github.com/KilledByAPixel/ZzFX)，1.4.0，MIT | 紧凑的参数化效果音，复古音色方便，但完整 BGM 需要另外编排 | 作为轻量替代方案记录，本轮统一使用 Tone.js |
| [Deterministic Lockstep](https://gafferongames.com/post/deterministic_lockstep/) | 记录输入占用小，但初始状态、随机数与数值运算必须一致；跨版本和平台不能只凭种子保证 | 记录实际消费的 Command、输入取消操作、模拟版本和地图版本 |
| [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/) | 状态样本不必重新运行 AI/物理，但频繁完整世界快照大，低频状态插值会漏事件或碰撞瞬间 | 采用混合方式：初始完整状态 + 动作流 + 定期含 RNG 的状态检查点 |

原有核心是 60 Hz 固定步长；渲染、音频和 AI 的随机数不应消耗物理随机数。仅记录移动/攻击按钮仍不够：暂停、租约到期、切换控制器会取消蓄力和缓存动作，所以这些状态修改必须进入录像。

回放不执行保存的 JS 或重新询问 AI。检查点恢复会创建新的对象身份，避免旧导航/几何缓存污染跳转。结构校验、版本检查和确定性校验各有不同用途；校验和用于发现漂移，并不构成文件认证。音乐按真实音频时钟演奏；加速模拟不提高音高，过密效果音需要限流。

## 验收清单

- [x] Tone.js 音乐分段、分层效果音、独立音乐/音效音量、静音和暂停恢复；浏览器实际声能及音频样本验证。
- [x] 动作流与状态检查点、开始/停止、文件导出/导入、跳转/暂停/倍速、回放结束和损坏文件提示。
- [x] 完整比赛、中途录制、控制切换、暂停/租约超时、换图、随机道具和动态地图的回放一致性。
- [x] 内置 AI 互战/观战；外部 AI 状态/动作协议、超时/非法输出隔离和可运行示例。
- [x] 0.25–8 倍可视模拟与回放；Node 无渲染加速、批量比赛、实际倍率测量和确定性比较。
- [x] 菜单/游戏界面、SDK API、类型声明与安装包同步，生产浏览器回归与文档。提交推送由 Git 历史记录。

音乐与效果音为新的程序化编排，以轻快打击乐和清晰战斗反馈贴近游戏风格，不使用原版音频文件，也不宣称原曲逐音符复原。

使用说明与协议见 [录像与 AI](replay-and-ai.md)，本轮测量与验收见 [0.6 验收记录](v6-validation.md)。
