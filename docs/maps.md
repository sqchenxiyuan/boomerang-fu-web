# 地图整理

63 张地图：57 张原版场景（含扩展）、1 张教程、5 张 Web 原创。本次整理包括三部分：

- 地图图鉴页
- 一套可重复跑的体检
- 对体检发现的问题做最小改动

## 地图图鉴

`npm run dev` 后打开 `/maps.html`，构建产物里是 `dist/maps.html`。游戏主菜单的地图说明旁有“地图图鉴 →”入口，会带上当前选中的地图。

- 每张卡片是按游戏镜头取景画的俯视示意图，内容有：
  - 地面、水、悬崖、冰面、移动地板
  - 墙、木箱、树和竹子
  - 传送门、出生点（编号）、道具点（黄色菱形）、边界（红色虚线）
- 卡片下方列出分组、大小、机器人平均回合时长和体检结论。
- 可以按分组（原版基础、原版扩展、教程、Web 原创）和特征标签筛选。特征标签有：水域、悬崖、坑洞、传送门、移动机关、坍塌地板、陷阱、开关、门、可破坏、植物、冰面。
- 可以按名称搜索，也可以按大小、回合时长或问题数排序。
- 点开卡片是实时 3D 预览，可以切换标准画风和像素风，可以打开“观看机器人对战”，让 4 个困难机器人真正跑起模拟，移动墙、坍塌地板这些机关会动起来。
- “在游戏中打开”跳到 `index.html?map=<id>`。主游戏读取 `?map=` 参数后直接选中并预览这张图。
- 详情里有体检数据和微调记录。

示意图代码在 `src/devtools/map-schematic.ts`，页面代码在 `src/gallery/`。

## 体检

```sh
npm run audit:maps                         # 全部地图，约 5 分钟
npm run audit:maps -- --only original-spin # 只重跑一张，其余保留
npm run audit:maps -- --rounds 10
```

结果写入 `src/devtools/map-audit-data.json`，并记下测量时的 `SIMULATION_VERSION` 和 `MAP_DATA_VERSION`。版本对不上时，图鉴页顶部会提示重新体检。

**静态检查（`auditMap`）**

- 以 0.2 单位为格子，判断每格能不能站人：地面、没有危险、和墙保持角色半径的距离。
- 从出生点出发做连通性填充，传送门算作连通。
- 检查以下几项：
  - 出生点和道具点有没有压在墙里、悬在水上或落在边界外
  - 出生点之间是否连通（地图有移动、坍塌机关或开关时，开局不连通属于设计，只记为提示）
  - 最近两个出生点的距离
  - 边界外和镜头取景外的可走面积

**机器人对局（`botAudit`）**

两个困难机器人在同一张图上打 6 个回合，记录：

- 平均回合时长
- 击杀、自杀和无击杀结束的回合数
- 进入缩圈的回合数
- 死因分布
- 每回合卡住的时长（3 秒内移动不到 0.4 个原版单位）

## 发现与改动

### 出生点微调

5 张原版地图共 5 个出生点和树木、石柱或滑墙重叠或贴得太紧，开局会被物理推开。原版地图的道具点和出生点共用坐标，所以对应的道具点也一起挪了。

| 地图     | 点  | 原因                 | 挪动 |
| -------- | --- | -------------------- | ---- |
| 孤岛     | 1   | 紧贴南侧石柱         | 0.05 |
| 孤岛     | 2   | 与东侧石柱碰撞体重叠 | 0.15 |
| 孤岛     | 4   | 与西侧桦树重叠       | 0.25 |
| 旋转轮盘 | 6   | 与竹子重叠           | 0.35 |
| 滑墙陷阱 | 5   | 紧贴滑墙             | 0.05 |

改动在 `src/core/map-adjustments.ts`，每一条都记下原坐标、新坐标和原因。加载地图时套用，`original-map-data.json` 一个字节都没改，它的 sha256 仍然等于 `MAP_DATA_VERSION`。`tests/map-adjustments.test.ts` 检查以下几点：

- 每条改动的原坐标与数据一致
- 每条改动的挪动距离小于 0.5
- 所有地图的全部出生点和道具点都站得住

因为模拟结果会变，模拟版本改为 0.10.0，0.9.0 录像不再兼容。

### 机器人僵持

体检里最大的问题不在布局，而是机器人在几张图上会互相僵持几分钟。共找到 3 个原因，对应 `tests/bot-stalls.test.ts` 的回归测试。

1. **召回卡墙**（丛林遗迹）。机器人没有武器时会一直按住召回。召回时人几乎不能动，而回旋镖被墙挡住回不来。现在召回 1 秒没有进展，机器人会松开召回，花 2 秒走过去捡。
2. **导航图没跟上移动墙**（曲折迷宫）。导航图的缓存签名只记录墙有没有被打碎，开关推出来的墙挡住通路后，机器人仍按旧路线顶着墙走。现在签名里加入移动障碍的位姿（按 0.25 单位、0.05 弧度量化），墙动了就重建导航图。
3. **站在岸边连不上路线**（庭院）。身体一半悬在水上时，按完整半径检查，起点到任何导航点都不通，寻路返回空，而且这一次寻路要把全图节点都试一遍。现在起点本身不安全时，只要求连接线的中心在地面上。连接点只在最近的 48 个节点里找。

另外，机器人在看不见对手、原地 1.5 秒没挪动时会绕路：尽量靠近对手，到不了就随机去一个道具点。这一条改善了旋转轮盘和旋转平台。这种绕路用的是 `findPath(..., { partial: true })`，默认的 `findPath` 语义没变，智能体观测里的路径也没变。

录像会记录每一帧所有角色的指令，机器人行为的改动不影响旧录像回放。

| 地图     | 修复前：平均回合 / 每回合卡住 | 修复后           |
| -------- | ----------------------------- | ---------------- |
| 丛林遗迹 | 960 秒只打完 2 回合 / 244 秒  | 3.5 秒 / 0       |
| 庭院     | 69 秒 / 124 秒                | 13.6 秒 / 0.8 秒 |
| 旋转平台 | 68 秒 / 114 秒                | 7.6 秒 / 0       |
| 曲折迷宫 | 66 秒 / 94 秒                 | 7.7 秒 / 0       |
| 旋转轮盘 | 37 秒 / 56 秒                 | 40 秒 / 17 秒    |

### 记录但没有改的

- **开局不连通**：旋转闸门、洗衣机、坍塌群岛、分割岛屿、轨道机关、旋转平台、庭院等图，出生点开局彼此不连通。这些图靠移动平台、坍塌桥或开关连通，属于设计。教程场地本来就分区。
- **边界外的可走地面**：27 张图的地面延伸到边界外。原版就是这样，走出去会触发出界计时。
- **陷阱迷宫**：120 块地板全是陷阱，机器人偶尔会走进已经塌掉的洞里。坠落本来就是这张图的主要死法，这里不改布局。
- **旋转轮盘**：有旋转长墙和 6 个传送门，追击本来就慢。机器人一直在动，只是回合偏长。
