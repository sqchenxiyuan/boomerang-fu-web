## 1. 移动是持续施力与惯性衰减

`Actor.cs:134–167` 的 walkSpeed=200、walkSpeedUnarmed=230、turningSpeed=12、dashSpeed=660、lungeSpeed=800 等名称并不全是最终每秒位移：走路、冲刺和突进主要作为力进入积分。`VectorExt.cs:38` 的 AddForce 在 Force 模式将 amount 乘 dt、除以 mass。Actor 的 mass 默认 1、drag 默认 11。

在普通干燥地面、timeScaler=1、无碰撞且未触及速度上限时，`Actor.cs:803–855` 对应的简化步进为：

```text
v_next = (v + force * dt) * max(0, 1 - 11 * dt)
x_next = x + v_next * dt
```

Unity 设置中的 fixedDeltaTime 为 **0.016666000708937645 秒**，接近 60 Hz。若按 Web 使用的精确 dt=1/60 计算，持械走路终端速度约 **14.84848 原版单位/秒**，空手约 **17.07576**。预制体 public walkVelocity=14.25 是独立字段，不能直接替代由施力、阻力算出的稳态结果。

`Player.cs:1252–1289` 为 MoveFaster 加 **1.4 倍走路力**，瞄准与普通回收则使用 aimSpeed/retrieveSpeed。两者是 protected、无 SerializeField、自定义属性数量 0，全程序集没有直接写入，正常初值为 **0**：按住瞄准/回收会停止继续推动身体，已有速度仍按阻力衰减；玩家还可以转向。松开瞄准后，若有方向输入，aimMoveLag 从 1 在 **0.5 秒**内恢复，力系数为 `1 - sin(pi/2 * aimMoveLag)`（Actor `2333–2341`，Player `1262–1274`）。

普通转向使用 `Quaternion.Slerp(..., dt * timeScaler * 12)`，动作启动使用 RotateSnapTo（Actor `1325–1338`）。在 60 Hz 下，对 90°目标的第一步转向是 **18°**；冲刺可立即转到输入方向，但不会抹去已有垂直于该方向的速度。

湿地另设 slideFactor=.25、drag=1，之后以 dt×7 恢复；冻结 drag=2（Actor `655–682`）。Web 当前统一使用干地阻力，尚未加入湿地/冰冻运动模型。

## 2. 冲刺包含 0.2 秒推进和完整恢复锁定

`Actor.Dash`（`1908–1957`）选择当前移动方向；没有输入时用最后朝向，锁定行走、转向、再次冲刺，取消瞄准，并把 **speedLimit×1.5=60** 的速度冲量叠加到已有速度。

`CalculateDash`（`1960–1983`）在 **0.2 秒**内施加逐渐减弱的力：

```text
dashForce(t) = 660 * cos(pi/2 * t/0.2)
```

它来自 `1-Easing.EaseIn(t)`，`Easing.cs:23–26` 的 EaseIn 是 `1-cos(pi/2*t)`。之后还存在阻力控制的惯性尾段，而非立刻静止。

**修正早期推断：普通未中断的冲刺锁定持续完整 0.55 秒，不能仅凭“剩余小于 .2”推成 .35 秒可再次冲刺。** `CooldownDash`（`1986–2006`）先判断 `remaining > dashCooldownMoveThreshold * dashCooldown`；该阈值字段正常为 0，并且整程序集没有直接写入、无序列化属性。因此在剩余时间仍正时，前一个分支持续锁定移动/转向，直到计时归零后才恢复。

MoveFaster 将实际冷却设为 **.55×.6=.33 秒**、冲刺力乘 **1.25**，并使计时器从 .04 开始，因此主动推进为 **.16 秒**（Player `1319–1327`）。提前 StopDash 可以扣除未用完的主动时间，也可由碰撞/危险检查改变路径（Actor `2009–2038`）；“完整 .55”只描述未取消的普通路径。

冲刺期间，常规刀/镖伤害和爆炸分支检查 IsDashing（Actor `1454–1458`、`1577–1583`）。这与 IsInvulnerable 是不同条件，不能扩写成所有环境伤害免疫。落水、挤压和边界另有处理。

## 3. 输入缓存与近战有独立时间窗口

`RewiredController.cs:42–47,66` 将移动轴限长，冲刺/攻击取 ButtonDown，投掷取 ButtonUp，持续瞄准取 held。`PlayerInput.cs:108–145` 的新输入优先级是：**近战 → 松开投掷 → 持续瞄准/回收 → 冲刺**。同一帧不应按 Web 代码排列随意改顺序。

失败输入进入最多 **8 条**的队列；冲刺保留 **.25 秒**，攻击和投掷保留 **.35 秒**（PlayerInput `49–53,158–172,224–250`）。成功动作清队列；重试按队列顺序，时间取 TimeKeeper 的游戏时钟，不能无条件等同现实秒数。

| 近战部分 | 原版普通值 | 证据 |
| --- | --- | --- |
| 有效攻击窗口 | .2 秒 | Actor `2350–2398`，IsAttacking setter `493–503` |
| 下一次近战冷却 | .66 秒 | Actor `2350–2398` |
| 突进施力阶段 | .1125 秒，`800 * (remaining/.1125)^3` | Actor `2240–2252` |
| 初始突进冲量 | speedLimit×.66=26.4 | Actor `2350–2398` |
| 行走/转向恢复 | .5 秒 | Actor `2200–2237` |

| 被缴械眩晕 | 有武器或冻结 .8 秒，空手 .5 秒 | Actor `2417–2428` |

攻击启动就开启相应碰撞体，不能仅凭挥刀动画自行增加固定伤害前摇。持械使用致命近战碰撞，空手使用单独的缴械碰撞并只打落一把镖（Player `2073–2085`）。近战可以中断冲刺；恢复期间方向仍受动作锁定，不能自由追踪输入转刀。

Player `1991–1995` 有 MoveFaster 相关攻击加速代码，但前面的持械/空手分支都已返回，正常流程无法据此证明加速生效。本轮没有给 Web 加上无条件“加速强化缩短攻击冷却”。

## 4. 格挡、对砍、护盾和受伤不是一个反馈事件

Actor `1454–1574` 包含伤害过滤、遮挡射线、正面点积、友伤条件等。飞镖格挡（Actor `1664–1708`）会结束近战、调用 StopLunge，并将攻击冷却通常设为 **.66×1.2=.792 秒**；有剩余攻击预算时另用 .15。满蓄力镖还触发眩晕/慢动作。对砍、盾碰撞走不同分支（`1710–1737`）。命中相同碰撞体还有默认 **10 个 fixed frame** 的抑制集合（`1741–1765`）。

StopLunge 只终止 lungeTimer 驱动力并可削弱速度，**不等同于清除整个 lungeCooldownTimer 恢复期**（Actor `2255–2265`）。GetStunned 调用 InterruptAttack，后者只关闭 IsAttacking，再清速度并启动推退（`2184–2187,2431–2439`）。不能把所有中断都实现成相同状态清零。

护盾通常一击消耗，击中后约 **.85 秒**暂时无敌（Player `2334–2342`）。StopShield 从 activePowerup 和历史队列同时移除 Shield（`2899–2919`），因此消耗过的盾不会因为回合切换自然恢复。护盾命中没有无条件停帧；刀镖死亡、飞镖格挡、少人数对砍等的不同停帧详见过场报告。

## 5. 投掷是松手动作，蓄力与弯镖有各自状态

Actor `2291–2303`、Player `1713–1739` 和已验证的 prefab 值共同确定：

```text
t = clamp((heldSeconds - 0.1) / 0.9, 0, 1)
power = 1 - cos(pi/2 * t)
```

前 **.1 秒**是启动阶段，随后 **.9 秒**非线性蓄力，约 **1.0 秒**达到满力。某些振动/视觉条件使用 aimTimer>=aimDuration，并不能反证 power 在 .9 秒已满。

Player `1058–1065` 仅在 aimTimer>.05 时记录 FixedUpdate 朝向历史，最多十个样本。投掷时比较最后移动方向与最早样本，旋转角度限制 ±90°（`1548–1638`）。没有方向输入、不能走路等状态会改变 throwDirection，投出方向不总等于渲染器刚插值出的角色朝向。

`Disc.cs:777–822` 的主要依赖如下：throwStrength 乘 `(1+power)`、speedLimit 乘 `(1+.5*power)`、飞出时长为 `.45-.15*power`；初始速度由施力结果再乘 9。初始镖默认不继承角色速度，只有特定显式参数才添加。普通攻击预算与 HasDiscs 共同控制能否投；代码没有一律禁止冲刺中松手投掷。

`Disc.cs:850–913` 在前方点积>.75、有视线、对手不冲刺等条件下进行轻微追踪；弯镖通过侧向力、立方起步以及超过飞出时长×1.2后的方向反转形成。它不是每帧固定角速度转向。

普通回收在无手持镖、有已投镖、不处于冲刺/突进等条件下，按住投掷键开始；retrieveCharge 以 **dt/4** 增长（Player `1713–1759`），不是按下就立即完成。Disc `915–949` 根据主人位置、QuartOut(charge)-.2 等量形成回收加力。掉落、缓慢失去归属、公共拾取、回返和控制镖是不同状态（Disc `536–643`）。按住回收时接回镖，要阻止随后松手意外再次投出。

本轮 Web 已把总蓄力改为 **1 秒**，力度计算由投掷模块采用上述曲线。其余飞镖仍保留简化：三个主要状态、简化弯曲/追踪、固定回返模型、角色速度继承、部分投掷动作限制，以及没有完全还原攻击预算。不能把修正蓄力称作完整还原镖物理。

## 6. 强化、坠落与比赛目标

Player `2740–2830` 管理最多 **3 种**唯一持久强化，超额按 FIFO 更替；重复获取不是无限叠加。火焰与黏液互斥，ReverseInputs 为独立的 6 秒临时状态，TimeImmune 是瞬态状态，缩圈是世界效果。常规初始化总会清临时状态，但只有 resetPowerups 条件才清持久队列（Player `747,791–796`）。Web 当前仅实现选定强化子集。

跌入危险区不会只有“立即死”一种路径：水面/悬崖分别用约 **.66/.74 秒**下落过程，前 **.33 秒**有一次冲刺救回窗口（Actor `1787–1807,1908–1929,2683–2734`）。Player `826–866` 支持 edgeAssist=0/.5/1，按危险边缘法向削减行走，冲刺/眩晕/bot 另走路径。Web 的走路硬边缘保护和落点后立即判死仍较简化。

越界一般先倒计时 **3 秒**，缩圈时为 **3.75 秒**（Player `1441–1501`）。Web 当前边界直接伤害、缩圈起始/回合上限是自己的节奏选择。MatchSettings 的 suddenDeathTime 默认 **180 秒**，不能把 Web 的 35 秒当原版默认。

原版支持 Kills 和 Survival 两种胜利条件：前者按击杀记分、处理友伤/自杀扣分（GameManager `2319–2346,2387–2391,2422–2440`）；后者给最后生存者加一（`2715–2721`）。MatchSettings 的 DeathMatch 类默认落在 Kills，团队/金镖设置使用 Survival；SettingsManager `655–715` 还按比赛长度、模式和人数定目标。**这只是类默认和计算分支，未读取用户实际选择。** Web 固定存活胜局/5 分目标不是所有原版对局的普遍规则。

## 7. 本轮 Web 修正与验证

`src/core/config.ts` 明确使用 **WORLD_SCALE=.4** 缩放运动力、速度上限和动作冲量，这是 Web 地图与显示尺度选择；动作秒数保留源代码基准。碰撞半径、地图几何和投掷物理没有全都按同一比例恢复。

`src/simulation/actors.ts` 已更新：持续施力与线性阻力、转向平滑与动作瞬转、余动保留、余弦冲刺力、完整冲刺锁定及 haste 分支、立方突进力、攻击窗口与恢复期分离、瞄准/回收停止推进、瞄准后 .5 秒恢复、新输入顺序、眩晕中接受失败输入缓存。Web 缓存当前保留攻击/冲刺两个槽并按年龄重试，尚非原版八条含投掷的队列。

`tests/feel.test.ts` **13 项全部通过**，包括以下关键断言（仅表示 Web 模拟）：

后续若继续追求相似手感，优先验证：同样的走停/转向/冲刺手势与原版录像比较；恢复原版投掷与回收的施力和攻击预算；完成碰撞体子变换并检查有效攻击形状；加入下落/救回、越界倒计时及湿滑地面；再按相同地图尺度校准镜头与命中特效。当前证据足以支持这些实现方向，但尚未取得原版运行对照结果。
