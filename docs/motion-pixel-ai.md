# 角色动作、像素风画面与机器人闪避

## 夸张动作与悬浮手脚

角色的手和脚不再用手臂连着身体，而是悬浮在身体两侧和下方。它们挂在一个只跟随朝向旋转的骨架上，所以身体挤压拉伸时，手脚不会跟着变形。所有姿态由 `src/rendering/character-motion.ts` 里的纯函数 `sampleCharacterPose(actor, time, { throwAge })` 计算，只依赖模拟状态和模拟时间。暂停、拖动回放、倍速时，画面和状态都保持一致。

| 状态 | 表现 |
| --- | --- |
| 待机 | 身体呼吸起伏，双手上下浮动、相位错开 |
| 跑动 | 每一步都有腾空和落地压扁；身体前倾、左右摇摆；双手大幅反向摆动；脚走弧线 |
| 蓄力 | 躯干扭开并后仰，投掷手拉到身后高处，另一只手指向前方；蓄满时轻微发抖 |
| 投掷后 0.36 s | 带回弹的甩出：躯干转过身体中线，投掷手扫到另一侧，身体向前拉伸 |
| 挥砍 | 在原有挥砍曲线上把扭转、前倾、踏步和挤压拉伸都放大，另一只手向后平衡 |
| 冲刺 | 沿运动方向拉长，身体前扑，手脚甩在身后 |
| 召回 | 双手前伸，身体后仰往回拽 |
| 眩晕 / 击退 | 绕圈摇晃、手臂软垂 / 失去平衡、双手举起 |
| 下落 | 双手乱挥 |
| 冰冻 | 所有关节定格 |

投掷后的动作由该角色最新那支飞镖的飞行时长推出来，而不是靠渲染层记录历史。动作和关键帧都是本仓库自己写的，没有使用 Godot 仓库里从原版导出的动画或角色资源。

## 像素风

菜单 → 画面风格 → **像素风**。选择保存在浏览器本地；SDK 浏览器入口对应 `game.setVisualStyle('pixel' | 'standard')`。

实现见 `src/rendering/pixel-pass.ts`，人物和地图同时生效：

1. 场景先渲染到低分辨率的 HalfFloat 目标，像素块大小按画面高度自动选择，目标是大约 300 行像素，限制在 2–5 个 CSS 像素之间。
2. 全屏合成时最近邻采样。先做色调映射，再按每通道 15 级做色阶量化，叠加较弱的 4×4 Bayer 抖动。
3. 用深度缓冲找轮廓：深度跳变时只把较近的一侧压暗，得到 1 像素宽的剪影描边。
4. 名牌放在单独的叠加图层，按全分辨率绘制在像素画之上，保证文字清晰。阴影切换为硬边。

## 机器人闪避

`src/simulation/ai-threats.ts` 是一个只读的飞镖前向模型。它用和模拟相同的力学推算未来约 0.8 s 的飞行：投掷力、回程拉力、自由滑行、阻尼、速度上限、撞墙反弹，还有朝目标的追踪。墙体检测只取飞镖附近的障碍物。

`src/simulation/ai.ts` 在每帧规划之前先做闪避判断：

- **来袭飞镖**：同时按"原地不动"和"沿当前速度继续走"两种情况判断是否会被命中，取较早或较险的结果。
  - 还剩 0.02–0.22 s 时挥砍弹开；满蓄力的镖不弹，因为弹满蓄力镖会被击退并眩晕 0.8 s。
  - 0.42 s 内冲刺。冲刺本身无敌，所以只评估落点：落点必须是安全地面、在边界内，而且飞镖朝新位置追踪后仍然打不到。
  - 时间更充裕时，选走开后余量最大的方向，并保持一小段时间，避免来回抖动。
- **预判出手**：对手蓄力瞄准自己时会被记下，出手瞬间就算感知到这把镖，不再等反应延迟；被瞄准期间横移。
- **近战**：对方的挥砍范围已经覆盖自己时，按难度选择反砍格挡或冲刺拉开。
- **着火**：只有移动距离能灭火，所以会朝远离火焰的安全方向持续奔跑，冲刺落点也要安全。
- **边界**：后撤目标在缩圈之前也限制在边界内。

难度参数（`DODGE`）：

| 难度 | 感知延迟 | 应对概率 | 弹镖倾向 | 被瞄准时横移 |
| --- | --- | --- | --- | --- |
| 简单 | 0.40 s | 35% | 15% | 20% |
| 普通 | 0.22 s | 72% | 35% | 55% |
| 困难 | 0.12 s | 90% | 60% | 80% |
| 极限 | 0.05 s | 100% | 80% | 100% |

基准测试：一个固定且无敌的投手在 7 个单位外，随机用不蓄力、半蓄力、满蓄力朝机器人投掷，3 个种子各投 30 次，统计飞镖命中率。

| 对象 | 命中率 |
| --- | --- |
| 站着不动 | 47% |
| 简单 | 40% |
| 普通 | 32% |
| 困难 | 19% |
| 极限 | 6% |

每回合第一次出手会被开局的投掷锁定吞掉，所以命中率的理论上限约为 50%。`tests/ai-dodge.test.ts` 固定了预判精度（36 帧内误差小于 0.05）和难度排序。4 个困难机器人在原版地图上，每帧平均多花约 0.1–0.2 ms。
