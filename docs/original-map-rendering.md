# 原版地图的 Web 几何与表现重建

日期：2026-10-29。本轮从安装包场景结构提取布局，在 Web 中重建地形和机关表现。原先五张 Web 地图继续保留为自定义布局；原版地图通过 `Arena.floors` 进入独立渲染路径。

## 原先地图相似的原因

旧渲染以一块矩形地面、矩形水坑、固定位置的围石/树木/旗帜/路石为基础，墙高、镜头和光照覆盖范围也基本固定。更换配色或障碍位置不足以表现原版的分离岛屿、旋转地板、孔洞、移动平台和高低不同的障碍。

新路径不添加固定庭院装饰或包围整个场景的地面矩形，而是直接渲染共享场景数据中的地板、障碍、表面与传送门。安全边界与实体地形分开处理，巨大辅助地板也不决定镜头范围。

## 坐标与共享数据

- 提取层把 Unity 物理 XY 转成 Web `(x, y) = (UnityX × 0.4, -UnityY × 0.4)`；渲染把 Web XY 放在 Three.js XZ 平面。
- `paths` 是相对于对象 `position` 的局部轮廓，`angle` 是 Web XY 中的弧度角；Three.js 的 `rotation.y` 使用 `-angle`。
- Shape 空间先使用 `(x, -y)`，挤出后绕 X 轴转 `-π/2`，使地形和碰撞使用相同的平面轮廓。没有再次把完整世界变换应用到已经展开的数据上。
- `polygon-geometry.ts` 使用 even-odd 填充：独立岛屿、孔洞、孔洞中的岛屿都可保留。轮廓的正反向不决定是否为洞；以包含层级的奇偶决定。
- 连续重复点、非有限点和零面积轮廓会被丢弃；不凭空增加碰撞厚度。圆形在显示时用有限边数近似，物理半径仍由共享数据定义。
- `Obstacle.baseHeight` 是模型包围盒底部的世界高度，`height` 是总跨度，两者相加才是露出地面的顶面高度；大量悬崖网格包含地下结构，不能从地面零点向上画完整跨度。
- `Floor.height` 来自物理碰撞体 Transform Z，不是地板可见顶面。显示统一从游戏平面 0 开始，仅叠加机关升降差量；该元数据保留供其他用途，不参与镜头高度。Plants 的碰撞体高度为 -2.4/-1.2，实际网格顶面约 0；TempleGarden 的碰撞体高度为 +2.7，实际地形顶面约 -0.0086；Drift/Split 顶面约 0，Spin 约 -0.188。证据见 `analysis/derived/v5-maps/floor-plant-height-evidence.json`。
- 机关视觉位移使用插值后的 `height - initialHeight`，按 `parentId` 累加祖先位移，因此平台下沉时附属物同步下沉。原始地图未初始化 `initialHeight` 时，以当前 `height` 为初始值。开关和植物已存储世界高度，只累加祖先位移，不再加祖先初始高度；CircleMaze/RaftCrusher 的父平台高度 -1.2 不会把世界高度 +0.5 的开关压入地面。
- `position`、`angle` 已由模拟更新为当前世界姿态。插值只施加当前到上一状态的差量，避免父级或当前变换被重复计算。

模型包围盒主要服务于表现。此处没有据此实现任意多层可行走空间；人物、飞镖和贴地特效仍沿项目现有游戏平面运行。

## 场景对象与时钟

`original-arena.ts` 为地板创建实际轮廓挤出体；不可见的区域不会因半宽/半高被补成矩形。坠落砖使用确定性的轻微明度差，使相邻砖块可辨；移动圆盘增加细边圈，并区分石盘与木筏配色。墙体使用多边形或圆柱轮廓，并按提取高度生成。树、竹和灌木使用碰撞轮廓作为树干或基部，增加简单的程序化冠层或展开叶片；岩台加内缩草色顶面，避免所有场景都读成同色石柱。

传送门是竖直门框、半透明门面与地面光斑；宽度参考触发区域，门高参考视觉包围盒。旧地图的圆形地面传送垫保留在旧渲染分支。开关使用简单杠杆；开门、移动障碍、地板预警和坠落都从模拟状态读取。`destroyer` 是逻辑区域，不生成可见模型。

`original-plants.ts` 单独渲染所有 `plant` 机关，不要求关联 Obstacle。全目录共 3,760 个植物实例，其中 Plants 有 1,025 株、TempleGarden 有 1,653 株、BambooGrove 有 390 株、Tracks 有 113 株。程序化六边灌木参考源 `HexBush00` 的标量范围：宽约 0.605、深约 0.532、相对组件底部 -0.086、顶部 1.416；不包含原模型顶点。每张地图使用一个不透明 InstancedMesh，跟随机关世界姿态和祖先升降，读取扰动方向与模拟时间产生摇摆，燃烧时变褐，被切断或失效后从活动实例中移除。TempleGarden/Temple 使用秋色。

非圆形移动平台采用木色，圆盘采用石色；Island、MiniIsland、Clouds、CloudSweep、Bridges 和 Mist 的顶面采用草色，Falling/Falling2 保留砖面。Toaster/Pier 的桥路轮廓属于合并地面碰撞体，当前数据没有独立桥面材质区域，路面仍与相邻平台共用程序化配色。

所有视觉时间来自 `state.time`。暂停时不会由浏览器时间继续推进门面纹理、闪光或地板抖动。机关移动和隐藏更新已有 Three.js 对象，不因每个导航 `Arena.revision` 重建地图。完整换图或新回合才重建场景。

## 边界、镜头和光照

安全边界保留源场景的中心、半宽、半高和旋转角。边线与标记单独旋转，人物警示保持世界坐标；接近边缘的透明度在边界局部坐标计算。`allowOutside` 开启时不显示限制线。

`arena-camera.ts` 优先按旋转安全边界的四角取景；没有边界时才从地板轮廓计算范围，再回退到旧地图尺寸。这避免 100 × 100 的辅助碰撞地板把镜头拉得过远。透视距离同时约束地面和边界内障碍的暴露顶面，并针对横屏和竖屏计算。原版分支采用 `Camera3D.cs` 中 `cameraAngle=(0,-0.4,-0.7)` 默认值对应的约 60° 俯角；旧庭院保留原镜头。光照阴影范围随地图调整，远距离镜头的雾范围也同步调整。

镜头适配只证明目标范围能投影到画面内；构图是否过空、角色是否足够清晰，仍需要浏览器截图验收。

## 资源与性能

静态地板与不可破坏障碍先按材质拆分挤出几何，再合并到专用静态根节点。移动或坠落地板、机关绑定对象、箱体和会失效的障碍保留独立节点，使模拟状态变化无需重建几何。动画地板拥有独立顶面材质，预警改色不会污染所有同色地板。

销毁场景时释放私有几何与材质，以及 InstancedMesh 的实例 GPU 资源；共享调色材质由既有材质缓存管理。测试检查静态合批后仍存在的网格包含非空、有限顶点，并验证破箱、沉降与暂停过程中对象引用稳定。

探索阶段的 `test-results/original-map-rendering/geometry-report.json` 记录的是 CPU 场景构建得到的网格/三角形计数。它不等于 GPU draw calls，也不作为帧率或显存结论。逐图浏览器与实际 GPU 性能由整体验收集中执行，避免并行浏览器相互影响测量。

## 验证与剩余差异

`tests/original-map-rendering.test.ts` 覆盖以下行为：

1. 58 图完整构建、静态合批及有限几何检查。
2. even-odd 孔洞、分离岛屿、嵌套岛屿的射线覆盖与面积。
3. 旋转墙体与真实轮廓，不增加默认矩形地面。
4. 200 静态墙体合批，同时保留可破坏箱体和移动地板。
5. 机关姿态插值、暂停确定性、坠落隐藏与资源引用保留。
6. 竖直传送门及模拟时钟驱动的闪光。
7. 多层祖先高度位移、附属植物/门/开关同步以及 destroyer 不可见。
8. 宽屏和竖屏的旋转边界取景，忽略巨大辅助地板。
9. 旋转边界的接近计算和 allowOutside 显示。
10. 埋地下的几何保留真实底部，镜头按地上顶面取景，静态合批后仍保持同样顶面。
11. 地板碰撞体的 +2.7/-1.2 高度不抬高或压低游戏平面，仅应用机关升降差量；全 58 图的初始活动地板位于平面 0。
12. 无障碍绑定的 1,000 株植物只用一个实例网格，覆盖插值、祖先升降、切断、失效、燃烧变色、扰动摇摆、暂停确定性与状态不变；全图活动植物数与实例数一致。

首次全图浏览器截图发现了 CPU 有限几何检查无法发现的语义错误：地下网格被抬到地面上，另有静态合批对象错误采用整块合并网格的范围。Enclosed 的 `c-1694` 应从约 -2.14 延伸到 1.1602，早期版本错误画成从 0 到 3.3002；FourCogs 的 `c-2386` 只使用 `m_StaticBatchInfo` 指向的子网格，不能使用整块包含大地板的 Mesh 范围。这两类问题均按源数据含义修复，没有以统一高度上限掩盖。

早期高度修正后，`scripts/original-map-rendering-verify.mjs` 集中截图 Enclosed、FourCogs、TrapMaze2、Teleportals、Falling 和 RaftPair；每图保留 tick 160 开局与 tick 340 两个时点，共 12 张真实 WebGL 截图，无浏览器或帧错误。

修正后的六张代表图已人工查看。Enclosed、FourCogs、TrapMaze2 开局双方人物完整可见，岩台/圆盘/迷宫通路可辨；Falling 的独立砖块可辨，RaftPair 两侧平台与移动木筏明显分离。tick 340 的 TrapMaze2 双角色与 Falling 的第二个角色已在模拟中落水，报告保留 alive 字段，不能把这种消失误判为模型遮挡。截图与状态在 `test-results/original-map-rendering/visual/`，具体 draw calls 在其 `report.json`；当时另有 CPU 对局测试并行，不把这些截图运行的帧率用作独占性能基线。全图 GPU 截图与性能由整体验收补充。

地板平面与植物补齐后，渲染测试为 12/12 通过，`npm run check` 退出码 0。追加 Drift、Plants、TempleGarden、Spin、Split、Tracks、BambooGrove、Toaster、Pier、Island、Clouds、Bridges、CircleMaze 和 RaftCrusher 共 14 张地图、28 张 WebGL 截图，无浏览器或帧错误。各图开局截图已目检：Drift/Split/Spin/Tracks 平台恢复，Plants/TempleGarden/BambooGrove 植物分布可见，TempleGarden 不再遮没角色，CircleMaze/RaftCrusher 的开关保持可见。本轮仍仅验收可见完整性，未将并行环境下帧率作为独占性能数据。

下列内容仍为明确近似：程序化配色、地板厚度、树冠与叶片、箱体装饰、门框细节、水面和远景，以及没有导出视觉模型的装饰物。包围盒高度与碰撞轮廓并不等于原版模型保真；地图数量与单测通过也不等于运行效果已经逐项与原版对照。
