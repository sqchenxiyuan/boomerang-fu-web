寻路修复不仅包括从预警地板撤离，还检查一条边中间穿过的预警地板；传送门虚拟跳转不受普通步行连线限制。静态地形图与移动障碍分开查询，固定地形不会每 0.15 秒重复从头计算。缓存根据地板是否启用、位置及形状旋转失效，圆形地板绕自身中心旋转不改变支撑范围。逃生优先检查近处候选，再通过图搜索转角；失败结果也遵守 0.2 秒反应间隔，避免每 tick 重试全场直线查询。

第一轮独占 CPU 的 Washer 同种子对照由 28.848 秒降为 2.547 秒，均为 2087 tick、34.333333 秒模拟、3 号胜出。单 tick 首次建图仍观察到约 201 ms 峰值。之后独占浏览器检测又暴露出 FourCogs 建图和 TrapMaze2 逃生的卡顿，经 CPU profile 定位后完成上述两处优化，并重新运行全部 351 项测试。CPU 检测和浏览器帧率是不同指标，均不作为所有地图/机器每帧稳定 60 FPS 的保证。

原始日志和截图位于本地 `test-results/`，不作为运行依赖。单测、有限数值检查或地图数量本身不能证明画面正确：浏览器对照发现了地下模型被抬至地上、静态合批整网格高度被误用、把 Floor 碰撞体 Z 当作可见地面高度，以及无障碍绑定植物未显示的问题。修正后完整重拍全部 58 图；3,760 株植物以实例网格显示，Plants/TempleGarden 在双静止角色样本中各约 68 draw calls。

## 已知实现边界

- 地形、出生点、碰撞、开关关联与时序来自原版静态资源。视觉使用碰撞轮廓、源模型高度范围和程序化模型，未复制原版网格、纹理、Animator、粒子、音乐或音效。
- 教程场地可练习，但没有原版引导任务/选择出生舱流程。当前为至多四人存活计分模式；目录中的其它模式元数据不代表 GoldenDisc、队伍赛等已经实现。
- Web 机器人自行实现；会绕障碍、经过传送门和撤离预警地板，不等同原版 AI。移动机关导航按短间隔重建，不能将 CPU 对局测试时长当作浏览器帧率。
- 圆形物理用解析半径，视觉以 32 边形近似。地面联合支撑的边缘查询采用采样，仍有与 Unity 物理解算细节不同的空间。
- 传送门冷却按两个模拟 tick 表达原版两个渲染帧；植被火冰传播、晃动与碎片是简化实现。道具落点从安全源出生候选中选取，未复刻原版运行时导航采样器。
- 尚未进行原版运行时逐帧同输入对照，不宣称像素级或每个物理边界等价。

## 使用

试玩站点默认原版封闭庭院。地图选择器按原版、扩展、教程场地及 Web 原创布局分组；`cycle` 只在同一集合内轮换并跳过教程。

SDK 0.5.0 导出 `MAPS`、`ORIGINAL_MAPS`、`CUSTOM_MAPS`，用 `mapId: 'original-four-cogs'` 等 ID 启动。默认核心 Session 仍为 `courtyard`，以保留此前接口行为。所有动态地形和机关状态由固定步长模拟拥有，可暂停、独立实例化和通过快照读取。

本轮先更新本地试玩与安装包，GitHub Pages 仍通过手动 workflow 发布。
