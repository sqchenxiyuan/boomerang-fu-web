# SDK 设计约定

此文件是实现前的边界设计，最终公开接口以 `sdk-api.md` 和打包类型声明为准。

## 状态、时钟、操作

模拟层只有固定步长状态推进，不读取键盘、DOM、RAF 或脚本。动作按人物 id 提交。内置机器人和人工键盘都作为控制器参与同一运行层的选择，不能在碰撞逻辑里绕过控制仲裁。运行层将输入的持续状态转成近战/冲刺按下边沿和投掷松开边沿。

无界面运行使用手动 `step()`；浏览器适配器持有唯一 RAF。绘制只读状态，事件通过订阅派发。各订阅者的快照隔离，不能通过回调引用写入权威状态。脚本只在战斗阶段执行，暂停、回合过渡与终局不积压动作。

0.4 增加无需复制世界的只读 `status` / `tick`。内建控制器可读会话内部状态；存在脚本时仍保留共同的预物理观察，再给每个脚本独立副本，防止前一脚本失败或输入清理影响后一脚本所见。浏览器 `onFrame`、公有 `getState()` / `snapshot()`、事件监听器继续获得隔离副本。SDK HUD 只在文字或可见性变化时更新 DOM；这不改变暂停/恢复契约。

`powerupPool` 是 1–14 个唯一道具的池，`startingPowers` 是最多 3 项的有序开场授予列表。两者都在构造和重开时校验并复制，开场道具在第一回合实际发镖时走普通 grant 逻辑；不能直接覆盖 `actor.powers` 绕过互斥、即时效果或库存规则。完整原版视觉和全部道具组合的还原程度与 SDK 参数校验分开验收。

## 控制权与接管

每个角色的默认来源是人工或内置机器人；获得外部控制后只接受当前凭据的动作。外部动作包含移动轴和三个按钮的持续状态，有有限的 tick 有效期。失效必须清空投掷状态且不能生成一次“松开投掷”。新动作中的非有限数值、非法 id、非法有效期在进入状态机前被拒绝。

脚本以同步 JavaScript 函数注册，每个 tick 获得隔离的观察值并返回动作。异常只停止对应控制器并发出错误事件；返回 Promise 不隐式阻塞时钟。脚本作为受信任的应用代码运行，不宣称隔离无限循环或恶意代码。

人工接管保存原控制来源，立即清空旧输入；退出时恢复脚本/机器人，并使旧外部凭据失效。重复接管、暂停中切换、倒计时/回合切换、重新开始和销毁都必须具有明确结果。外部调用不能通过再注入旧凭据抢回人工控制。

## 生命周期与产物

- 核心入口：不加载 Three.js 或 DOM，Node 可直接导入并运行整场。
- 浏览器入口：创建可嵌入画面与输入适配器，可开始/暂停/恢复/重开/销毁。
- 类型声明、ES module、示例、README 与版本进入 tarball；原版分析产物、源游戏文件、开发快照、测试缓存不进入 SDK。
- 保留本地试玩站点，增加独立控制演示：外部动作注入、脚本开始、人工接管、恢复脚本、控制状态可见。
- 从隔离临时目录安装最终 tarball，执行 Node 完整对局和浏览器挂载/控制/销毁，才算封装验收完成。

## 必须通过的行为用例

1. 未注入时角色静止；相同动作序列在不同绘制频率下得到相同固定 tick 状态。
2. 非人工初始角色也可由外部控制；每个 tick 只执行一种控制来源。
3. 外部连续按住近战/冲刺不会每 tick 重复按下；投掷只在有效松键边沿发生。
4. 到期、暂停、接管、回合变化与重开清空旧动作，不误投。
5. 人工接管后旧凭据不能控制，退出接管后脚本可恢复且无旧蓄力。
6. 脚本异常、回调异常、非法参数、状态快照被外部修改不会污染模拟。
7. 销毁移除 RAF、DOM 监听、WebGL 与音频资源，不能继续操作已销毁实例；不同实例输入不互相干扰。
8. 正式包里存在公开 SDK，开发接口缺席；Node/浏览器示例无需源码路径或原版安装目录。
