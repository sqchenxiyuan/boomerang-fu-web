# 第二阶段目标与验收

用户目标：依次详细分析原版游戏机制、操作手感、过场动画；扩展更多地图；测试后封装 SDK，将运行过程与人物操作分离，支持外部注入、人工接管和 JS 脚本控制。

## 实施顺序

1. [x] 基于当前安装版本建立机制/时序/动画证据表，区分反编译默认值、序列化参数、运行观察与 Web 设计选择。
2. [x] 按分析修正影响操作的差异，补齐回合/地图过渡动画及可复现验证。
3. [x] 新增至少四张具有不同空间布局与战术取舍的地图，提供地图选择和轮换；验证出生点、可达性、遮挡与完整对局。
4. [x] 地图与玩法验收后封装独立 SDK：纯模拟与浏览器显示分开，提供生命周期、状态快照、事件、动作注入及 JS 控制器。
5. [x] 人工/脚本/外部控制明确仲裁与切换；接管清空旧按键、旧租约失效、暂停不误投，按键边沿由 SDK 处理。
6. [x] 提供可运行的 JS 脚本示例与浏览器接管示例，并从打包产物验证调用，不依赖开发专用调试入口。
7. [x] 更新 README、SDK API、分析报告与验收记录，执行类型检查、规则/整场测试、真实浏览器操作和独立包消费验证。

## SDK 边界

- 运行层拥有唯一模拟时钟和状态；控制器只提交动作，不直接写人物属性。
- 核心支持固定步长的手动推进与无 DOM 使用；浏览器适配层负责 RAF、键盘/手柄、画面及声音。
- 每个人物同一时刻只有一个控制源。人工接管是显式控制切换，退出后可恢复原脚本；外部操作有有效期，失联不会一直移动。
- 脚本通过 JavaScript 模块/函数接入，有独立可运行示例；不要求将任意聊天文本当代码执行。
- 发布包保留正式 SDK 导出，开发诊断接口仍不进入产物；不上传或发布外网，交付本地可安装包及演示页面。

## 完成证据

分析报告带来源定位；每张地图完成机器人整场和截图验收；输入控制切换具有回归测试；浏览器演示真实人工接管；独立目录安装 tarball 后 Node 与浏览器调用通过；无脚本/资源错误或状态泄漏。上述事项缺证据时不标记完成。

上述门槛均已验收：92 项逻辑测试、17 项主站浏览器检查、10 项 SDK 浏览器检查、正式构建和最终 tarball 独立 Node/浏览器消费均通过。具体结果和适用边界见 [第二阶段验收记录](v2-validation.md)。
