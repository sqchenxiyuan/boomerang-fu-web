# 第三阶段：缩圈、死亡与淘汰反馈对齐

用户目标：原版还有缩圈、死亡特效等，继续对齐。原安装文件与已保留的静态证据是机制依据；本阶段不把代码读取描述成原版实机观察。

## 完成条件

- [x] 核对原版边界形状、触发时刻、目标位置/尺寸、收缩曲线、圈外宽限与回圈重置；替换现有中心圆形即死规则。
- [x] 地图显示实际判定矩形，包含边界线、危险区域与目标位置提示；人物圈外闪烁、回场方向和剩余时间可见，主站与 SDK 显示一致。
- [x] 死亡记录保留原因、方向、位置、时间及确定性表现种子；切片、爆炸压扁、落水、悬崖、越界具有不同演出，尸块/贴花能正确持续和清理。
- [x] 下落有水/崖时序及早期救回窗口；正在下落的最后一人不能被提前判胜；死亡无敌闪烁不能使尸体重新出现。
- [x] 对齐直接相关的命中停顿、镜头/音效和淘汰文案，区分原版可证事实与程序化视觉/音频适配。
- [x] 纯模拟边界和下落测试、确定性表现测试、原规则/地图/完整对局回归通过；真实浏览器检查缩圈、逃回、不同死亡效果、暂停、换图与多实例清理。
- [x] 更新公开 SDK 类型/选项/事件文档并构建新的安装包；从独立包验证核心和浏览器运行，源码与产物保持一致。
- [x] 记录截图、验收结果、证据出处和剩余原版差异后进行完成审计。

## 分工与证据

缩圈规则见 `sudden-death-analysis.md`；死亡调用与资源见 `death-feedback-analysis.md`；浏览器验收场景与视觉原始参数见 `v3-feedback-test-plan.md`。这些报告由对原安装资源的独立问题调查支持，普通仓库源码编辑不需要 REA 原生反汇编器。

REA Codex 注册存在，但本会话未暴露 REA MCP 工具；只读 doctor 验证注册后继续使用现成 CLI、ILSpy 与 UnityPy，没有修改客户端配置。既有程序集证据身份及新增派生文件保存在忽略的 analysis 目录。
