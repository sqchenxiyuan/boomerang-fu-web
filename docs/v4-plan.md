# 第四阶段：开场武器、完整特殊道具与流畅特效

用户目标：核对开场持械与特殊道具是否复刻，补齐缺失玩法，优化武器/道具特效流畅度。继续使用本地预览；只有用户明确要求时才部署 GitHub Pages，提交不自动部署。

## 完成要求与证据

- [x] 核对真实普通回合的初始化、Go、发镖时序，区分菜单展示与战斗；按用户偏好提供清楚、可验证的开场持械行为，不把 Web 改动称作原版参数。
- [x] 明确原版 14 个正式道具和非正式 TimeImmune 的区别；逐项记录作用、输入、持续时间、互斥/替换、跨回合与主要组合。
- [x] 全部正式道具进入可玩流程：加速、穿墙、反向输入、护盾、爆炸、分裂、传送、火焰、额外回旋镖、冰、伪装、遥控、缩圈、诱饵。不能只有图标或特效，没有实际机制。
- [x] 处理最多三个持久强化、瞬时/负面效果、火冰互斥、武器库存、死亡和新回合重置；保留 SDK 的输入/所有权/暂停/确定性契约。
- [x] 道具具有可辨认的拾取/持有效果/武器反馈和说明，提供便于实际体验的本地道具试验入口，仍使用正式模拟规则。
- [x] 采集真实浏览器性能基线，减少每帧复制/DOM 写入、粒子资源分配和 draw calls；武器拖尾、蓄力、挥砍和命中流畅衔接，暂停不跳帧，生命周期不泄漏。
- [x] 每种道具和代表性组合有针对性机制验证；实际公开 Session/键盘流程验证开场武器、拾取和主要操作。视觉 fixture 和实际战斗证据分开记录。
- [x] 全部回归、正式构建、独立 SDK 包与本地预览通过；保留可重跑脚本、源码哈希、性能前后结果与实现差异后再完成审计。

## 当前核实的基线

本轮开始时只有 shield/haste/explosive 三项，Go 后 1.2 秒自动发镖。原版 PowerupType 有 15 个非 None 值，但 AllPowerups 的正式列表为 14 个：TimeImmune 不在正常池内。原版普通回合的 1.2 秒发镖有静态调用链支持，详细核对写入 v4-powerups-analysis.md。原版未启动，不能把静态证据称为原版实机表现。

实现前性能基线与测试方案由 v4-performance-baseline.md 记录。最终浏览器、性能与 SDK 验收已绑定同一份生产源码，见 v4-validation.md。生命周期验证覆盖容量上限、重复 reset 与 destroy 的资源释放，未将短样本等同于长期无泄漏保证。
