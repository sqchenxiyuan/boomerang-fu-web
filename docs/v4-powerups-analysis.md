# V4：十四种强化、组合规则与开局发镖

调查日期：2026-10-28。目标为本机 `F:\SteamLibrary\steamapps\common\Boomerang Fu` 的安装产物。本轮仅静态读取托管程序集和 Unity 资源，没有启动原版、执行原版程序集或读写玩家存档。下文将安装产物能证明的规则与 Web 实现分开；Web 测试通过不等于已经实测原版手感。

## 结论及证据边界

1. 正式强化列表是 **14 项**。`PowerupType` 有 15 个非 None 标志，但 `Powerup.AllPowerups()` 明确排除 `TimeImmune`。普通正面候选列表为 13 项，`ReverseInputs` 以负面结果覆盖正常随机结果。
2. `SlimeDisc` 是内部旧名称，显示名称使用 `powerup_icedisc`，应呈现为**冰冻回旋镖**，不是黏液。
3. 普通回合从空手入场；`Go()` 后延迟 **1.2 秒**自动补一把镖，有 ExtraDisc 则补两把。角色选择 UI 也显式隐藏左右镖。原版不存在“必须去地图捡第一把武器”的普通开场路径。
4. 正面持久强化最多三槽、按获取顺序替换；火与冰互斥。反向输入和缩圈不占持久槽。未消耗的持久强化跨回合保留。
5. 伪装由静止自动触发；诱饵由本回合首次成功冲刺或传送触发。传送有己方在外飞镖即可尝试，并不要求空手，而且先于普通冲刺冷却判断。
6. 爆炸半径不能只抄类默认值：安装资源中普通/火爆半径为 **12**，冰爆为 **17**，小型爆炸再乘 **0.5**；Grenade 实际引信为 **1.33 秒**。

### 不计入十四项的 TimeImmune

`PowerupType.cs:6–21` 中存在 TimeImmune=4096，Player 2816–2820 也有设置计时、粒子和 `SlowMoTimeWarp(6.3, .2, 1, .4)` 的实现。Player 1080–1096 以倒数 timeScale 补偿，期限还受慢动作恢复条件影响，不能简单解释成“现实时间 1.5 秒”。

但 `Powerup.AllPowerups()` 的明确枚举、LevelManager 正常概率列表都没有它，`GetPowerupNameString` 对它返回空字符串。因此本轮不把它宣传为正常可拾取的第十五项。此结论不等价于证明所有调试、特殊模式或外部调用均无法触达该分支。

## 槽位、负面结果和随机池

`Player.cs:2740–2831` 的 `StartPowerup` 是主要状态入口：

- 普通持久效果首次获得时追加 history；重复获得不会改变原先顺序。
- 第四个不同的持久效果到来时，清除 history[0] 的位并移除最旧记录。
- FireDisc 清除 SlimeDisc 及其 history，SlimeDisc 也会清除 FireDisc。
- ReverseInputs、TimeImmune 和 ShrinkingBounds 不按普通持久槽追加。
- 通用 FIFO 分支只清 flag/history，没有逐个调用 StopShield 等清理回调。不能据此宣称原版即时删除全部附属状态；同理失去 ExtraDisc 标志不会立即删除已经手持的额外武器。

PrepareRound 只在第一回合传 `resetPowerups=true`（GameManager 1727），后续回合保留持久强化。临时反向输入等在 Init/死亡时清理；破盾后移除该能力，不在下一回合恢复已消耗盾。角色真正持镖数由 `HasDiscs` 维护并映射至左右手，不等于拥有 ExtraDisc 标志与否。

普通候选列表在 `LevelManager.cs:68–84` 明列 13 项正面效果。`SelectRandomPower` 先筛掉无用重复、已足够武器的 ExtraDisc、持 Fire 时的 SlimeDisc，以及当前不允许的缩圈，再考虑负面覆盖：

```text
全场已有至少一次非负面随机选择
且非 conventionMode
且设置允许 ReverseInputs
则以 (5 + 当前玩家 activePowerup 位数 × .25)% 概率替换为 ReverseInputs
```

这里的 `powerupsCollectedSoFar` 是 **LevelManager 全局计数**，在 BuildMatchPlaylist 重置，不是每位玩家自己的拾取次数。持有状态位数量也不严格等于 UI 三槽数量。

`CyclePossiblePowerups`（1157–1168）另外管理全局轮换队列：候选较多时暂时移除已抽到的效果，队列超过四项才放回最早的一项。这与玩家的三槽 FIFO 是不同机制。空 useful 列表的 fallback 中，缩圈判断看起来与主筛选方向相反；本轮只记录原句，不擅自把它改写成理想算法。

GoldenDisc 模式排除移动加速、穿墙冲刺、传送、遥控、双镖与缩圈。先前看到的场景序列化 mask=12286 只是场景初始化值；`SettingsManager.LoadModifiedMatchSettings` 可加载保存值或构造新 MatchSettings，而新设置调用 `AllPowerups()`。没有读用户存档，因此不能拿场景 mask 断言当前玩家设置禁用了新增强化。

### 地面火、冰与冻结

火/冰持有者没有天然全局免疫。Actor 699–795 的处理检查冲刺、无敌、湿地、结冰状态和格子 owner，不检查“我有 FireDisc 所以我免疫火”。自己的冰积累速度为 .2 倍，仍可冻住自己。离开冰后积累以每秒 .5 的速度消退；反复接触可以继续累计。

燃烧角色通过移动累计灭火：`extinguishAmount += distance / dashDistance * .24`，到 1 灭火。按类中 dashDistance=11.06 算，需要走约 46.08 原版单位；该值为代码字段依据，不能把表达式误算成 dashDistance×.24。Web 使用 .4 空间缩放，相应为约 18.43 单位。冲刺接触火会清除接触火格；站冰、湿地、新盾也有灭火路径。

冻结持续 7 秒；按动作可以每 .2 秒削减 7/12 秒。原版仍有冰块惯性/轻微挣扎位移，Web 的冻结运动暂时用静止近似。燃烧到期直接走火焰死亡，不因届时正在冲刺而取消；Web 已对应独立 `fire` 死因。

## 开局：为什么人物先空手

普通 DeathMatch 的调用链可以明确定位：

```text
GameManager.PrepareRound
  → Player.Init(startDiscs: 0, resetPowerups: 首回合)
  → GetReady / SpawnIn
  → 按顺序入场（最多四人时每人相隔约 .4 秒）
  → Ready 显示 1 秒
  → Go 显示，titlesShowing=false
  → GameState=Playing，Player.Go()
  → RespawnDisc(waitTime: 1.2, numDiscs: 普通1 / ExtraDisc2)
  → 等待 scaled time
  → PickUpDisc(null) → HasDiscs 增加 → 手部武器显示与生成特效
```

主要定位：GameManager 1613–1865（Init 调用在 1727）；Player 721–839、873–945、981–1021、2944–2979；UIMenuRoundTitles 96–145。

Go 字样继续显示约 .7 秒后隐藏；**1.2 秒补镖从 Go 解锁开始计算，不是从 Go 字样隐藏开始算**。trailerMode 可把等待改成零，HideAndSeek 的 seeker 有独立流程；不能把这些例外混成普通对局规则。

`Player.Init` 设置 `HasDiscs=0`、`character.SetMeleeDiscs(0)`；Go 解锁行走、转身并安排补镖。等待期间是短暂空手阶段，可以移动，空手近战规则也不同于持镖切斩。没有发现需要寻找名为 GiveDiscs 的函数，真正等价的发镖逻辑是 RespawnDiscRoutine→PickUpDisc(null)。`Level.playerStartingDiscs` 在已查普通 PrepareRound 路径中没有作为参数使用；这不是对所有动态路径的全局“永不使用”证明。

### 角色选择菜单是否显示镖

`UIPlayer.SetCharacterModel`（52–76）切到 UI 时调用 `character.InitCharacter(CharacterMode.UI)`；`CharacterPlayer.cs:211–214` 在 UI 分支显式执行：

```csharp
rightDisc.SetActive(false);
leftDisc.SetActive(false);
```

游戏内 `SetMeleeDiscs`（247–268）则根据 0/1/2 分别显示无镖、右镖、双镖。资源里 WatermelonChar 的 BoomerangL（3016）/BoomerangR（2934）默认 active=true，不能推翻运行代码的显式隐藏。UI AnimatorController 1718 所检查的引用片段只有 Transform 绑定，未见激活武器的浮点曲线；这只是辅证，决定性证据是上述模式切换代码。
