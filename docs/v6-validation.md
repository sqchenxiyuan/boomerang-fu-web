## 动作录制与状态录制的实际比较

四机器人 courtyard，seed 8751，先得 2 分，1337 tick（22.28 模拟秒）：

| 保存方式 | JSON 大小 | 取舍 |
| --- | ---: | --- |
| 每 tick 保存完整 GameState | 10,146,904 字节 | 这是逐帧状态 JSON 的累计实测体积，未实现独立的状态流播放器 |
| 初始状态 + 动作流 | 175,213 字节 | 通过从混合录像移除中间检查点测得；跳转必须从头计算 |
| 动作流 + 每 600 tick 完整检查点 | 192,528 字节 | 正式实现，可从最近检查点重演 |
| 上述混合录像 gzip | 约 15,957 字节 | 正式下载格式；元数据时间戳会引起少量字节变化 |

三场样本从最近检查点跳到 70% 位置，实测约 **5–16 ms**，不代表复杂地图的最坏耗时。`original-plants` 的 600 tick 压力片段刻意每 60 tick 建检查点：11 个检查点共 4,769,064 字节 JSON / 约 289,420 字节 gzip。继续按此高频率录制，4260 tick 时容量保护自动结束：33,793,057 字节，仍可解析和跳到末尾，比赛继续运行。默认检查点为每 600 tick。

因此采用混合录像；录像最大模拟时长 30 分钟，同时有 32 MiB 保守估计的自动结束阈值，导入解压上限 64 MiB。复杂地图可能先达到容量上限。文件的有限数值、嵌套状态结构、版本、操作和检查点计数均在载入前检查；状态字段缺失或类型错误即使重新计算哈希也会被拒绝。

跨当前 Chrome/Node 时观察到约 10⁻¹⁹ 的飞镖曲率尾差，因此校验将非整数规范到小数点后 9 位；模拟状态本身不量化。它是漂移检测，不是文件认证，也不保证跨所有 JS 引擎、架构或未来版本逐位一致。回放保存状态与动作，不是视频；镜头粒子/音频不作为逐采样录像保存。

## AI 与模拟速度

`scripts/v6-node-verify.mjs` 完成三场四机器人比赛，校验回放和最终比分。HTTP 示例实测 **162 次请求**，同时覆盖错 tick、超过 64 KiB 的响应、21 次超时和 AbortSignal 取消；失败没有阻塞其他角色或生成意外投掷。CLI 另外实际跑完两个 seed 并生成可回放 gzip 文件。

固定步长时钟运行相同 120 tick，在 0.25/1/4/8× 下的完整状态相同，时钟步数均为 120；无渲染 RAF 样本耗时约 8.07 / 2.02 / 0.52 / 0.27 秒。生产 Three.js 页面回放的所选 1/4/8× 实测约 **0.98/3.65/6.66×**，最终状态相同，未改变物理步长。

Node 无画面三场样本在初次单独运行时约 **69–122×**，最终与浏览器、安装包验收并发运行时约 **40–75×**。这是当前机器与这些地图的测量；原版密集植被/机关更慢，外部推理/网络耗时也会限制倍率。异步策略超时可取消；同一 JS 线程中的同步死循环不受 Promise 超时保护，不可信策略应独立进程运行。

## 音频验证

`scripts/v6-audio-clock-verify.mjs` 用真实 Web Audio 离线渲染菜单、对战、决胜和胜利四个 5 秒 WAV。测得 RMS 约 0.004–0.011，峰值约 0.049–0.140；均有非零音乐信号，无削波。对战样本叠加 12 类效果音。实际浏览器验证独立音量、静音、暂停和恢复；静音/暂停后的测量值降至 10⁻⁵ 以下。失焦立即暂停音频时钟，不依赖后台 RAF。

高频调用 200 批音效，限流后处理数百个事件，无调度异常；两个独立音频上下文的暂停、transport 和增益互不影响。以上证明声音生成与调度正常，**不替代人工听感评价**。完整开源许可保留在 `THIRD_PARTY_NOTICES.md`，并进入站点及 SDK。
